# IMPROVEMENT PLAN — Посадочная страница CanvasDesk

> Анализ позиционирования проекта и план улучшений **canvasdesk.tech** на основе best practices 15 эталонных open-source проектов.
> Дата: 4 октября 2026 · Продукт: [danku13/CanvasDesk](https://github.com/danku13/CanvasDesk) · Лендинг: этот репозиторий (`index.html` + `config.js`)
> Контекст на момент анализа: 5 звёзд, проекту ~1 месяц, статус по README — «ищем первых 5 внешних пользователей, которые сами построят модель и вернутся к ней второй раз».

## TL;DR

- CanvasDesk продаёт **правильную** главную ценность («модель считает себя сама», а не «value-edges и DAG») и **правильную** сегментацию на 4 персоны (Logseq-паттерн). Две главные дыры воронки: на первом экране **статичная картинка вместо живого пересчёта**, а сообщество (Telegram/Discord) видно **только в самом низу страницы**.
- У всех 15 эталонов: продукт на первом экране, ровно один primary-CTA с формулировками «без регистрации», лицензия у верха страницы, сообщество «в одном клике отовсюду» и только проверяемые числа в social proof.
- Для конверсии в тестирование ЦА должна за 5 секунд увидеть: **свою задачу → живой пересчёт на канвасе → «Открыть в браузере без регистрации»**. Для вступления в чат: **понятную роль канала и доказательство, что автор отвечает**.
- Что нельзя: непроверяемые цифры и «trusted by», обещания поддержки/SLA/сроков roadmap, сокрытие ограничений платформ, buzzword soup, лобовые атаки на конкуренты, финансовые гарантии.

## 2. Позиционирование CanvasDesk сегодня

**Как заявлено:**
- Позиционирующий контракт ADR-0007: «CanvasDesk — визуальная система математического моделирования».
- Hero: «Канвас, который считает сам» + подзаголовок про capacity, юнит-экономику, runway. Ведёт с результата, а не с архитектуры — совпадает с практикой всех 15 эталонов.
- Ключевая замена стека: «без раскидывания по Miro + Excel + Google Docs + PowerPoint».
- Секции лендинга: personas (4 карточки «кто ты → зачем → доказательство»), stats (45 шаблонов, 39 MCP-инструментов, <10 мс, 5000 нод @ 60 FPS), trust («1000+ тестов в CI», «Без телеметрии»), compare (vs Excel/Miro/Obsidian Canvas), matrix платформ, early («Станьте ранним пользователем»), FAQ, #community.
- README честен про ограничения платформ и про стадию: «ищем первых 5 внешних пользователей».

**Сильное:** результат-ориентированный hero; persona-секция (у гигантов это редкость, у нишевых инструментов — работающий паттерн Logseq); доказательная конкретика вместо оценок; двуязычность с приоритетами платформ по локали; честность ранней стадии.

**Слабое (по итогам сравнения с эталонами):** статичное hero-изображение там, где эталоны показывают живой продукт; сообщество доступно только в футерной секции (у 5/5 группы B — ещё и в шапке/футере постоянно); лицензия AGPL не видна на самом лендинге; нет zero-friction строки под CTA; нет agent-friendly документов (llms.txt) при том, что MCP — одна из ключевых фич.

## 3. Ответы на пять ключевых вопросов

### 3.1 Кто целевая аудитория

Ядро — 4 персоны (заявлены в README и продублированы в секции personas):

| Персона | Боль / задача | Где обитает | Раннее конверсионное качество |
|---|---|---|---|
| **Solution / Technical архитектор** | Выдержит ли сервис 10k rps, сколько реплик, где узкое место при ×2 — без опыта на проде | Хабр, TG-каналы по архитектуре, Discord-сообщества | Высокое: инфраструктурные шаблоны и Erlang-C уже готовы, результат нагляден |
| **Продакт-аналитик / финансовый аналитик** | Юнит-экономика: LTV при таком CAC, runway при −1 пп churn | Хабр, продуктовые TG-каналы, LinkedIn | Высокое: 18 шаблонов юнит-экономики, what-if дельты «было → стало» |
| **Продакт-оунер / менеджер** | Защитить бюджет и решение перед C-level/инвесторами моделью, а не презентацией | Management-сообщества, конференции | Среднее: нужен «экспорт для защиты» — сейчас слабо проявлен |
| **ИИ-аудитория (MCP)** | Собрать модель по текстовому описанию, проверить числа агентом | X/Twitter, Discord AI-сообществ, GitHub | Высокое и самое вирусное: MCP — растущая тема, 39 инструментов — уже готово |

Вторичная аудитория: Rust/WebGPU-энтузиасты и потенциальные контрибьюторы (CLA), наблюдатели open-source.

Вывод: RU-трафик приходит с Хабра (поэтому Habr — primary карточка в RU-приоритетах — верно), EN-трафик — с GitHub и X. Целевая метрика владельца («построит модель и вернётся второй раз») лучше всего достигается на архитекторах и аналитиках, а ИИ-персона даёт охват и шум.

### 3.2 Как авторы подают value этой аудитории и почему так

1. **Консолидация стека** («одно место вместо Miro + Excel + Google Docs + PowerPoint»). Почему: ЦА уже собрала зоопарк инструментов; замена четырёх инструментов — осязаемая выгода, а не абстрактная «продуктивность».
2. **«Диаграмма и есть формула»** — снятие главного возражения против визуального моделирования: нарисованная модель ничего не считает, а табличная невидима. Это implicit-противопоставление (паттерн гигантов: контраст без называния конкурентов).
3. **Доказательная конкретика** (45/39/<10 мс/5000@60FPS/1000+ тестов). Почему: при 5 звёздах социальное доказательство через «trusted by» невозможно; продаёт только демонстрация работающей математики. Это drawio-паттерн (принципы + честные цифры вместо логотипов).
4. **Честность ранней стадии** («ищем первых 5 пользователей», «Firefox — экспериментально», Linux/macOS — частично). Почему: tldraw прямо пишет «not accepting contributions», Jellyfin — «We do not run servers for users», drawio — «does not support real-time collaborative editing». Проговорённые ограничения повышают доверие и фильтруют нецелевых.
5. **ИИ-подача одной человеческой фразой** («Опишите модель словами — агент соберёт»). Проверенный рынком шаблон: Excalidraw продаёт MCP одной строкой «Let an agent draw into your workspace».
6. **Двуязычность и региональные приоритеты платформ** — редкая практика (из 15 только Vue имеет полноценный i18n) и конкурентное преимущество для RU-аудитории.

### 3.4 Что должна увидеть ЦА CanvasDesk, чтобы конвертироваться

**Путь 1 — в тестирование продукта** (целевое действие: открыть веб-версию, покрутить модель, вернуться второй раз):

1. За 5 секунд — своя задача: persona-карточка уже работает («Архитекторам: capacity и узкие места — до деплоя»).
2. **Живой пересчёт**: автоплей GIF/видео или интерактив, где меняют `rps`/`churn` и граф пересчитывается. Статичный `hero-canvas.png` — главный тормоз воронки: продукт динамический, а первый экран статический.
3. Снятие барьеров строкой под CTA: «Открыть в браузере · Без регистрации · Бесплатно · Открытый код» — дословный паттерн drawio («Free forever • No sign-up required • No lock-in»).
4. Открылась **готовая эталонная модель**, а не пустой канвас (паттерн Immich: demo-сервер с готовыми данными). Первый «вау-момент» ≤ 60 секунд от клика.
5. Мостик из продукта в сообщество: «Собрал модель? Покажи в чате — автор читает всё» (Home Assistant и n8n строят сообщество как продолжение продукта).

**Путь 2 — в сообщество** (целевое действие: вступить в Telegram/Discord):

1. Сообщество видно **отовсюду**: иконки TG/Discord в шапке и/или футере (у всех 5 из группы B) — секция внизу страницы не единственная точка входа.
2. Названа **роль канала** («Best for»): Telegram — «официальный чат: быстрая помощь и новости», Discord — «обсуждения сценариев и поддержка». Базис уже реализован в `roles.*` — усилить в подзаголовке секции.
3. Приглашение **через выгоду**, не через просьбу: «Задайте вопрос — автор отвечает лично», «Ваш сценарий может стать следующим шаблоном». Паттерн Supabase: CTA «Join us on Discord» сверху, social proof сразу под ним; паттерн n8n: благодарность вместо флексинга численности.
4. **Доказательство жизни чата**: цитата реального обмена (Logseq цитирует Discord-пользователя с ником и источником), закреплённый тред. При 0–5 участниках счётчики не показывать — показывать доступность автора.
5. Для RU — Telegram primary, для EN — Discord primary (паттерн Jellyfin: честно указать предпочитаемый канал).

## 5. Приложение: краткие карточки эталонов

**Группа A — канвас/диаграммы/заметки**

- **Excalidraw (133k★, MIT)** — лендинг = сам редактор, «No account is needed. Just start drawing»; MCP продаётся одной фразой («Let an agent draw into your workspace»). *Урок: нулевой трение и продукт вместо рассказа о продукте.*
- **tldraw (51k★, source-available)** — лендинг нарисован на собственном канвасе; strip «50.7K GitHub · 8.73K Discord · 478K npm/week»; честное «We are not accepting contributions at this time»; llms.txt «for your coding agent». *Урок: агент-friendly документы как маркетинговый аргумент.*
- **AFFiNE (73k★, MIT + source-available)** — «Write, Draw, Plan, All at Once»; FAQ прямо на лендинге («open-source Notion and Miro alternative»); незавершённое честно метится (Beta)/(Coming soon). *Урок: прямое определение категории работает лучше эвфемизмов.*
- **drawio (8.5k★, Apache-2.0, 100M+ users)** — trust-строка «Free forever • No sign-up required • No lock-in»; принципы вместо логотипов: «No Paywalls», «Independent: Not VC-funded»; прямо пишет, чего нет. *Урок: доверие строится на декларируемых принципах, а звёзды не обязательны.*
- **Joplin (57k★, AGPL-3.0)** — «Free your notes»; download-first с CTA в конце каждого фича-блока; секция «In the Press» с цитатами Lifehacker/PCMag; монетизация Cloud не конфликтует с open source. *Урок: AGPL не мешает конверсии, если честно и спокойно его показывать.*

**Группа B — community-driven инфраструктура**

- **Home Assistant (91k★, Apache-2.0)** — сообщество в самом подзаголовке hero («Powered by a worldwide community»); секция «Join The Community» с тремя кнопками: Forums/Chat/Newsletter; дисклеймер «No technical support!» рядом с контактами. *Урок: приглашение = названия каналов без хайпа.*
- **Immich (116k★, AGPL-3.0)** — минималистичный SPA без всякого хайпа; demo-сервер с открытыми кредами; Discord и GitHub иконками в шапке каждой страницы; live-бейдж Discord в README. *Урок: попробовать до установки — решающий паттерн.*
- **Jellyfin (58k★, GPL-2.0)** — «The Free Software Media System»; честность о каналах («Matrix is preferred… Discord is bridged»); все комнаты перечислены по именам; «We do not run servers for users». *Урок: когда два чата — честно указать предпочтительный.*
- **Supabase (111k★, Apache-2.0)** — секция `<section id="community">`: заголовок «Join the community» → кнопка «Join us on Discord» → стена реальных твитов с хендлами; routing каналов «Best for:…» в README; счётчик звёзд постоянно в шапке. *Урок: CTA сообщества ставится непосредственно над social proof.*
- **n8n (206k★, fair-code)** — social proof полоса сразу под hero: «206.5k stars» / «200k+ community members. This wouldn't be possible without you»; MCP — отдельный пункт навигации; никогда не называет себя open source. *Урок: численность сообщества подаётся как благодарность.*

**Группа C — гиганты**

- **VS Code (193k★)** — «The open source AI code editor»; анимированная симуляция IDE на первом экране; единственный action — OS-определённая кнопка Download; llms.txt для агентов. *Урок: продукт и есть первый экран.*
- **React (250k★, MIT)** — hero без кнопок вообще; лендинг = обучающий нарратив с живыми сандбоксами; соцдоказательство: «2M developers monthly» проверяемо. *Урок: документация как главная воронка доверия.*
- **Vue (212k★, MIT)** — «The Progressive JavaScript Framework»; playground в главной навигации; когда-то знаменитое честное сравнение с конкурентами удалено из v3-доков. *Урок: даже гиганты уходят от лобовых сравнений.*
- **Syncthing (89k★, MPL-2.0)** — hero = само определение («continuous file synchronization program. Your data is your data alone»); ноль маркетинговых цифр; ранжированные цели проекта в README. *Урок: ценности и определение могут полностью заменить social proof.*
- **Logseq (45k★, AGPL-3.0)** — сильнейшая персона-сегментация (студенты/академики/писатели/PM/разработчики) + уровни навыка; «Join our Discord — users online currently»; цитаты юзеров с ником и источником. *Урок: персона-модель CanvasDesk валидирована именно этим эталоном.*
