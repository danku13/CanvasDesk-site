# CanvasDesk-site

Лендинг проекта [CanvasDesk](https://github.com/danku13/CanvasDesk) + панель быстрого редактирования контента.

🌐 **Живой сайт: [canvasdesk.tech](https://canvasdesk.tech)** (GitHub Pages, деплой автоматом из `main`)

Чистый **HTML + JS без сборки и зависимостей**: клонировали — и сайт уже работает. Контент страницы полностью управляется конфигом, код править не нужно.

## Состав репозитория

| Файл | Назначение |
|---|---|
| `index.html` | Лендинг (EN/RU, определяется по языку браузера, переключатель в шапке) |
| `admin.html` | Админка: редактирование всех текстов, ссылок, медиа и приоритетов платформ |
| `config.js` | Дефолтный контент + хелперы (общий для обеих страниц) |
| `config.json` | Продакшен-переопределения (создаётся экспортом из админки) |
| `CNAME` | Кастомный домен `canvasdesk.tech` для GitHub Pages (не удаляйте) |
| `.nojekyll` | Отключает обработку Jekyll на GitHub Pages (нужен, не удаляйте) |

## Как устроен контент

Страница собирает конфиг из трёх источников — верхний перекрывает нижний:

1. **`localStorage`** — черновые правки из админки, видит только тот, кто правил (кнопка «Превью»);
2. **`config.json`** — продакшен-контент, видят все посетители;
3. **`config.js`** — базовые дефолты.

Такой порядок позволяет сначала поиграться с текстами локально, а затем «опубликовать» их одним файлом.

## Локальный запуск

Вариант 1 — просто открыть `index.html` двойным кликом. Всё работает, включая админку.

Вариант 2 — мини-сервер (рекомендуется: так работают и «Превью», и `config.json`):

```bash
# любой из способов:
python3 -m http.server 8080        # затем откройте http://localhost:8080
npx serve .
```

## Редактирование контента

### Через админку (рекомендуется)

1. Откройте `admin.html`.
2. Заполните поля: тексты EN/RU, ссылки на платформы, медиа, порядок кнопок.
3. **💾 Сохранить** → откройте **👁 Превью** — правки сразу на странице (они живут в `localStorage`, посетители их пока не видят).
4. Когда всё устраивает — **⬇ Экспорт**: скачается `config.json`, содержащий **только ваши изменения** относительно дефолтов.
5. Положите `config.json` в корень сайта и закоммитьте (см. ниже).

> Админка экспортирует дифф, а не весь конфиг — если в `config.js` появятся новые поля/секции после обновления, они не будут «заморожены» старым `config.json`.

### Вручную

Правьте `config.js` напрямую — там же подсказки `// TODO` для ещё не заполненных ссылок. Если `config.json` существует, он перекроет ваши правки в `config.js`, поэтому либо редактируйте `config.json`, либо удалите его.

## Самостоятельное развёртывание

Сайт статический — подойдёт любой хостинг статики. Ниже пошаговые инструкции для популярных вариантов.

### Вариант 1. GitHub Pages — уже настроен

Сайт публикуется из ветки `main` (корень) на **canvasdesk.tech**, адрес в настройках: `Settings → Pages`.

Обновление сайта = обычный `git push` в `main` — GitHub Pages пересоберёт сайт сам (~1 минута).

Через командную строку обновление выглядит так:

```bash
git clone https://github.com/danku13/CanvasDesk-site.git
cd CanvasDesk-site
# ... правите файлы или кладёте config.json из админки ...
git add -A
git commit -m "content: update links and texts"
git push
```

> Если Git спрашивает логин/пароль: в качестве пароля используйте Personal Access Token
> (GitHub → Settings → Developer settings → **Fine-grained tokens** → Generate; права: `Contents: Read and write` на этот репозиторий). Удобнее один раз войти через [`gh auth login`](https://cli.github.com/).

### Вариант 2. Netlify (бесплатно, приватный репозиторий — ок)

**Самый быстрый способ, без git:**
1. Откройте [app.netlify.com/drop](https://app.netlify.com/drop).
2. Перетащите папку с сайтом в окно браузера — сайт онлайн через ~10 секунд.

**Способ с автодеплоем из репозитория:**
1. [app.netlify.com](https://app.netlify.com) → **Add new site** → **Import an existing project** → **GitHub**.
2. Выберите `CanvasDesk-site`.
3. Ничего не меняйте: Publish directory = `.` (по умолчанию), команд сборки нет → **Deploy**.
4. Каждый `push` в `main` будет автоматически обновлять сайт.

### Вариант 3. Cloudflare Pages (бесплатно, быстрый CDN)

Сайт полностью статический — **сборка не нужна**. Но не оставляйте настройки сборки пустыми: автоопределение Cloudflare видит в корне `config.json`, а такое же имя файла используется генератором Hugo для своего конфига. В итоге Cloudflare решает, что это Hugo-проект, запускает `npx hugo` и деплой падает:

```
✘ [ERROR] Command failed with exit code 1: npx hugo
  npm error could not determine executable to run
```

**Создание проекта (правильные настройки сразу):**
1. [dash.cloudflare.com](https://dash.cloudflare.com) → **Workers & Pages** → **Create** → вкладка **Pages** → **Connect to Git** → репозиторий `CanvasDesk-site`.
2. На шаге «Set up builds and deployments» заполните вручную:

   | Поле | Значение |
   |---|---|
   | Framework preset | **None** |
   | Build command | `echo "static site, nothing to build"` |
   | Build output directory | `/` |

3. **Save and Deploy** — через ~минуту сайт будет доступен на `https://<имя-проекта>.pages.dev`.

**Если проект уже создан и падает с `npx hugo`:**
1. Откройте проект → **Settings** → **Build** → **Build configuration** → **Edit**.
2. Выставьте значения из таблицы выше (preset `None`, build command `echo "static site, nothing to build"`, output directory `/`) и сохраните.
3. Вкладка **Deployments** → у последнего деплоя меню **⋯ → Retry deployment**.

**Альтернатива — загрузка через CLI, без привязки к Git:**

```bash
npx wrangler login
npx wrangler pages deploy . --project-name=canvasdesk
```

> Свой домен для Cloudflare Pages подключается в **Custom domains**, но требует, чтобы DNS домена обслуживался Cloudflare (смена NS-серверов у регистратора). Пока сайт живёт на GitHub Pages, переключать NS `canvasdesk.tech` на Cloudflare **не нужно** — иначе GitHub-версия перестанет открываться. Для проверки Cloudflare-деплоя используйте адрес `<имя-проекта>.pages.dev`.

### Вариант 4. Vercel

1. [vercel.com/new](https://vercel.com/new) → импортируйте `CanvasDesk-site`.
2. Framework preset: **Other**, всё остальное по умолчанию → **Deploy**.

### Свой домен — canvasdesk.tech (подключён)

Сайт доступен на **https://canvasdesk.tech** (плюс апекс-редиректы с www и github.io). Текущая конфигурация:

- **CNAME-файл** в корне репозитория (одна строка: `canvasdesk.tech`) — обязателен для режима «Deploy from a branch», не удаляйте: именно он сохраняет домен при деплоях.
- **DNS у регистратора** (reg.ru):
  - `@` (апекс) → 4 × A-записи GitHub Pages: `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`
  - `www` → CNAME на `danku13.github.io` (тогда `www.canvasdesk.tech` будет редиректить на апекс)
- **HTTPS**: после того как DNS заработал, GitHub сам выпускает сертификат Let's Encrypt (обычно до часа). Затем в `Settings → Pages` появляется галочка **Enforce HTTPS** — включите её.
- Проверить, куда указывает DNS из разных стран: [whatsmydns.net](https://whatsmydns.net/#A/canvasdesk.tech).

Хотите сменить домен — поменяйте строку в `CNAME`, записи DNS и поле «Custom domain» в `Settings → Pages`.

## FAQ

**Кнопки платформ не видны на странице.** Кнопки в блоке «Выберите платформу» и футере показываются только для платформ с непустой ссылкой — заполните `links.*` в админке.

**Правки из админки видны только мне.** Так и задумано: `localStorage` — черновик. Опубликуйте их экспортом `config.json` в репозиторий.

**Как вернуть всё к дефолтам?** В админке: **↺ Сброс** (уберёт локальный черновик). Если на проде нужен откат — удалите или откатите `config.json` в репозитории.

**Порядок кнопок платформ разный для языков?** Да: списки `priorities.en` / `priorities.ru` редактируются в админке (секция «Приоритеты платформ») — можно менять порядок, добавлять и убирать платформы для каждой аудитории.
